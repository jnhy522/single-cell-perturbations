## Morgan Fingerprint Quick Guide

What the heck is dis <img src="../emoji/yippy.jpg" width="20" height="20" style="vertical-align:middle">

To understand Morgan Fingerprints, we have to understand **Extended-Connectivity Fingerprints (ECFP)**. The explanation below is largely based on [this guide](https://chemicbook.com/2021/03/25/a-beginners-guide-for-understanding-extended-connectivity-fingerprints.html), which concisely broke down each step of the fingerprint generating process for a non-chemist like me. 

_(for my ML-inclined audience, this is conceptually similar to convolutional operations: like the convolution operator in CNNs that apply the same function in all directions before global pooling, ECFPs use iterative circular hashing to capture local chemical environments, also before a global pooling step ฅ^•ﻌ•^ฅ)_

There are <img src="../emoji/four.png" width="30" height="30" style="vertical-align:middle"> basic steps in ECFP:  

<ol> 
<li> <b>Step 1 - Initial Atom Assignment</b>: each atom in the moelcule is assigned a unique integer identifier, which is generated by hashing a list of properties about the atom itself. More on this later. </li>
<li> <b>Step 2 - Update Atom Identifier</b>: each atom collects its identifier and the identifiers of its immediate neighbors into an array. A hash function is used to reduce this array back into a new, single-integer identifier, replacing its old identifier. This process is repeated iteratively: in the next iteration, the atom will have a updated (again!) identifier which accounts for the neighbors of its neighbors. The number of iterations is up to you.</li>
<li> <b>Step 3 - De-duplicate substructures</b>: remove duplicate features, duh. </li>
<li> <b>Step 4 - Form bit-array</b>: once all identifiers are generated, reduce this to a bit array so your computer can read it. Voilà! </li>
</ol>

Got it? Okay, let's try with a concrete example. Say we have a molecule called Butyramide. It looks like this :3

#### <b>Step 1 - Assign unique identifier to each atom</b>

First step is to assign an identifier to each atom based on the **Daylight atomic invariant rules**, which denotes the six properties of an atom in a molecule: 
<ul>
  <li>Number of non-hydrogen immediate neighbors</li>
  <li>Valency minus the number of connected hydrogens (in other words, total bond order ignoring bonds to hydrogens)</li>
  <li>Atomic number</li>
  <li>Atomic mass</li>
  <li>Atomic charge</li>
  <li>Number of attached hydrogens</li>
  <li> [Whether the atom is a part of at least one ring] (this is an additional property often used in ECFP, 1 if yes, 0 otherwise) </li>
</ul>
These features are then hashed into a value. Let's try this for atom 4:
<ul>
  <li>Number of non-hydrogen immediate neighbors = 3 (atom 3, 5, and 6)</li>
  <li>Valency minus the number of connected hydrogens = 4 </li>
  <li>Atomic number = 6</li>
  <li>Atomic mass = 12</li>
  <li>Atomic charge = 0</li>
  <li>Number of attached hydrogens = 0</li>
  <li> [Whether the atom is a part of at least one ring] (this is an additional property often used in ECFP, 1 if yes, 0 otherwise) = 0</li>
</ul>

So the tuple of features = (3, 4, 6, 12, 0, 0, 0). This order is fixed by convention to ensure that the hash is reproducible. Hashing this with the python hash function:

```python
identifier = hash((3, 4, 6, 12, 0, 0, 0))
print(identifier) 
# -2155244659601281804
```
This process is repeated for each atom. The identifiers after the first iteration is:
```python
1: -4080868480043360372
2:  8311098529014133067
3:  8311098529014133067
4: -2155244659601281804
5: -3602994677767288312
6:  8573586092015465947
```
Notice how atom 2 and 3 have the same identifier because they are essentially identical as individuals.  
Keep in mind that the identifier value depends on the hashing function. Different hash functions may produce different identifiers. The idea is to have a consistent function.  

#### <b>Step 2 - Iteratively update identifier</b>
The next step is to update these identifiers to include information about their neighbors. 
<ol> 
<li> An array is initialized to include the iteration number and the initial identifier of the atom. For example, for the first iteration of atom 4, the array will be 

```python
[(1, -2155244659601281804)] 
```
</li>
<li> Next, we add two more numbers to this array for each non-hydrogen neighbor. The first number is the bond order with that particular atom (1, 2, 3, 4 for single, double, triple, aromatic bonds respectively), and the second is that atom's current identifier. These are sorted before hashing using number pairs to avoid ordering dependency. This sort is essential to make the resulting identifier independent of arbitrary order in which neighbors happen to be numbered Without it, the same substructure could hash differently depending on input atom order.

For example, atom 4 is connected to atom 5, 3, and 6 via a single, single and double bond. The feature array now becomes

```python
[(1, -2155244659601281804), (1, -3602994677767288312), (1, 8311098529014133067), (2, 8573586092015465947)]
```
This is converted to a proper list,
```python
[1, -2155244659601281804, 1, -3602994677767288312, 1, 8311098529014133067, 2, 8573586092015465947]
```
then hashed to get an updated integer identifier for atom 4. 
```python
identifier_updated = hash(tuple([1, -2155244659601281804, 1, -3602994677767288312, 1, 8311098529014133067, 2, 8573586092015465947]))
print(identifier_updated)
# 3790237506519639747
```
This is repeated for all atoms. The identifiers after the first iteration now becomes:
```python
1: -3879702859024654160
2:  2648074263463118673
3:  9209025387859845960
4:  3790237506519639747
5: -8399737669368778010
6:  3271801898087186516
```
Notice how atom 2 and 3 no longer have the same identifier because they are connected to different environments.
</li>
<li> Similarly, for the second iteration, we’ll do the exact same thing but using the updated identifiers instead. </li>
<li> After each iteration, the identifiers are added to a feature list created from the previous iteration. For example, after the initialization step, we have 6 identifiers in our feature list. After the next iteration, we’ll have 6 more identifiers added. After the first iteration, our feature list becomes: 

```python
[-4080868480043360372, 8311098529014133067, 8311098529014133067, -2155244659601281804, -3602994677767288312, 8573586092015465947, -3879702859024654160, 2648074263463118673, 9209025387859845960, 3790237506519639747, -8399737669368778010, 3271801898087186516]
```
</li>
<li>After two iterations, our list becomes: 

```python
[-4080868480043360372, 8311098529014133067, 8311098529014133067, -2155244659601281804, -3602994677767288312, 8573586092015465947, -3879702859024654160, 2648074263463118673, 9209025387859845960, 3790237506519639747, -8399737669368778010, 3271801898087186516, 7820245418060671737, -8234949431280515543, -5902629546112570760, -3660103599533977242, -5964710996914813053, 8916398073441202914]
```
</li>
</ol>
The number of iterations depends on use. Typically, two iterations are sufficient for similarity or clustering, while activity learning often benefit from the greater structure detail with three or more iterations.


#### <b>Step 3 - Removing duplicate structures</b>
When we increase the number of iterations, multiple atoms may end up generating the same substructure in the molecule. Like we saw earlier for atoms 2 and 3, their generated identifiers during initial iteration were the same. In this case, either atom 2 or 3 can be dropped. 
<b> Since a fingerprint is meant to record which substructures are present, two features describing the identical substructure are redundant.</b>

But what if the identifiers are not the same but the substructures are duplicates? In our molecule, the same substructure is generated with Oxygen or Nitrogren as the center atom after two iterations.
<p align="center">
  <img src="duplicate_structs.png" alt="Description" width="250" />
</p>
However, the identifiers for the atoms themselves are different, which makes sense because they started off at different atoms. So how do we deduplicate them?  

To identify duplicates, each identifier keeps track of the set of bonds that it represents in a particular molecule. At each iteration step, the set of bonds is updated to include:
<ol> 
<li> the union of all bonds in the central atom’s bond set from the previous iteration </li>
<li> the neighbor atom’s bond sets from the previous iteration, and</li>
<li>all attachment bonds</li>
</ol>
This list of bonds defines the substructure that is covered by the newly generated feature. Before any new features are appended to the fingerprint set, they are checked to see if structural duplicates exist. When two features cover the exact same set of bonds, even though their identifiers differ, the tie-breaking rules are: 
<ul>
<li> <b>Across iterations</b>: if a newly generated feature covers the same bond set as a feature from a previous iteration, the new one is discarded. The feature from the smaller iteration (smaller diameter) survives, because it represents the more compact description of that substructure. </li>
<li> <b>Within the same iteration</b>: if two features generated at the same iteration cover identical bond sets, the one with the smaller identifier is kept and the other is dropped. This is an arbitrary but deterministic rule, ensuring reproducibility regardless of atom ordering. </li>
</ul>
So the ordering of survival preference is: lower iteration first, then lower hash value as the tiebreaker. Here's another illustrative example: 
<p align="center">
  <img src="duplicate_structs_2.webp" alt="Description" width="300" />
</p>
The left and middle features discovered in the last iteration are identical as ones discovered in the previous iteration. One of them is discarded. 

After removing duplicates, our final fingerprint is: 
```python
[-4080868480043360372, 8311098529014133067, -2155244659601281804, -3602994677767288312, 8573586092015465947, -3879702859024654160, 2648074263463118673, 9209025387859845960, 3790237506519639747, -8399737669368778010, 3271801898087186516, -8234949431280515543, -5902629546112570760, -3660103599533977242]
```
#### <b>Step 4 - Converting to bit array</b>
The last step is to convert this into a computer-readable bit array.
<ol> 
<li> User chooses length of the fingerprint array (eg. 1024).

```python
import numpy as np
fp = np.zeros(1024)
print(fp)
# array([0., 0., 0., ..., 0., 0., 0.])
```
</li>
<li> Then we initiate a zero-array of the decided length</li>
<li> Divide each identifier with the array length and calculate the remainder for all identifiers.

```python
remainders = [908, 331, 244, 520, 475, 176, 849, 840, 707, 742, 84, 553, 632, 358]
```
 </li>
 <li> Lastly, set the values in the bit array to 1 at indices equal to the remainders. In other words, set the values to 1 in the positions 908, 331, …, 358. </li>

 ```python
 for x in remainders:
    fp[x] = 1
 ```
This bit array is our final fingerprint for the molecule Woohoo!
</ol>

#### <b>Bit collision</b>
This happens when two structurally distinct features folds to the same index. For example, let’s say you end up with a hash values of `-4080868480043360372` and `-14439656419269748`. 
```python 
-4080868480043360372 % 1024 = 908
-14439656419269748 % 1024 = 908 ← collision
```
Since a bit is binary (0 or 1), the second feature setting an already-set bit adds no new information. The array can't record "two different features live here" or "this feature appeared twice" — it just stays 1. So you lose the ability to distinguish those features.

This can be resolved if we increase the size of the array to 2048.
```python 
-4080868480043360372 % 2048 = 908
-14439656419269748 % 2048 = 1932  ← resolved
```
When you hash `n` distinct features into an array of length `L`, the chance of at least one collision follows the birthday-problem logic - collisions become likely once n approaches √L. A molecule with ~50 features will collide often in a 1024-bit array but rarely in a 2048- or 4096-bit one.

But this does not mean the bigger the better 😏. As long as `L` is finite, some inputs will always share a remainder. Only an unfolded/sparse representation (storing the raw hashes directly) avoids it. There is a trade-off between information stored vs data sparsity. Out of the 1024 bits, generally only ~3-30 bits are 1’s. Increasing the size will almost double the number of zeros while not guaranteeing zero collisions. Typically, 1024 is sufficient.

And there you have it - <mark style="background-color: #d2cbdd"> the ECFP <i>is</i> the Morgan Fingerprint</mark>, but a modernized version. H.L. Morgan designed the original algorithm to canonicalize unambiguous chemical structures, whereas ECFP repurposed it to build a fingerprint for similarity and machine learning.The API keeps Morgan in the name to credit the underlying algorithm. <img src="../emoji/yippy.jpg" width="20" height="20" style="vertical-align:middle">

#### <b>RDKit</b>
In RDKit, you pass in an empty `bits` dictionary and `nBits` to `GetMorganFingerprintAsBitVect`. The function returns a `BitVect` of default length 2048, with the structure: 
```
{ bit_position: ((atom_index, radius), (atom_index, radius), ...) }
```
Each key is a bit that has a value of 1. Each value is a tuple of `(atom_index, radius)`, aka the environment in the molecule that hashed to that bit. So: 
<ul>
<li> <b>atom_index</b> is the center atom of that environment</li>
<li> <b>radius</b> is how many bonds out the environment extends to (0 = just the atom and its invariants, 1 = atom plus immediate neighbors, 2 = out two bonds)</li>

</ul>
To give you an idea, an example `bits` output would look like this: 


## How do we use this for ML?
Morgan FP is a binary vector where eact bit represents the presence (1) or absence (0) of a specific substructure in a defined radius in a molecule.  

We can replace the one-hot encoded `sm_name` (as well as `sm_lincs_id`) with ECFPs. When `sm_name` is used as a training parameter, model learns the identity of the drug. The value of fingerprints is that they provide chemical structures as learning parameters to the model, so when predicting novel cell x drug combo, the model can borrow from chemically similar drugs.
